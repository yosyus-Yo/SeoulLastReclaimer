# 웹 게임플레이 확장 진단·모션 제작 계획

서울의 마지막 회수자 · 2026-09-08 · v0.2 검토 반영

**문서 목적:** 현재 웹 프로토타입의 작동 범위와 빈 부분을 확인하고, 점프·수직 탐험·실내·낙하 피해 및 전투 모션을 다음 제작 단계로 정리한다. **이번 작업은 문서 작성이며, 아래 신규 기능은 아직 구현하지 않았다.**

검토 기준은 `web` 코드, 실제 포함된 플레이어 GLB, 기존 제작 문서다. 기준 커밋은 `612bc60`이며 Unity의 구현 여부를 웹의 구현 여부로 간주하지 않는다. 기존 디자인 패키지와 수치표는 보존한다. 향후 실행 계획·일정 확정 전 사용자가 이 문서를 검토한다.

## 1. 먼저 알아야 할 결론

1. 현재는 **3D로 그린 평면 액션 게임**이다. 플레이어 이동·전투·상호작용·경로 찾기는 X/Z 좌표 중심이고, 플레이어의 표시 높이는 0으로 고정된다. 점프 효과만 붙여서는 상자 위에 서거나 실내 2층에서 싸울 수 없다.
2. 대기·걷기·달리기 외의 플레이어 전용 모션이 없다. 파편격, 방벽, 회피, 회수는 **규칙이나 시각 효과가 있는 것**이지 해당 행동의 신체 애니메이션까지 완성된 상태는 아니다.
3. 점프·등반을 먼저 넣고 나중에 맵 경계를 고치면, 기존 통제선을 넘어 배경으로 탈출하거나 보스·구조 목표를 건너뛸 수 있다. 높이 충돌, 이동 가능 표면, 경계, 체크포인트를 함께 설계해야 한다.
4. 첫 목표는 도시 전체 확장이 아니라 **골목 → 낮은 장애물 → 건물 내부 → 계단/옥상 → 지정 외벽 → 안전한 귀환**이 연결되는 작은 시험 구간이다. 이 구간에서 이동·전투·낙하·복구가 모두 검증된 뒤 다른 맵으로 확대한다.

### 기존 기획과 이번 요청의 관계

| 항목 | 원안 / 현재 | 이번 방향 |
|---|---|---|
| 수동 점프 | 원안 GDD에서 명시적으로 제외, 웹에도 없음 | 사용자 요청으로 추가 방향 확정. 높이·조작·타이밍은 제안 단계 |
| 외벽 등반 | 기존 핵심 조작에 없음 | 신규 요구. 모든 벽 자유 등반인지 지정 경로인지 범위 확인 필요 |
| 건물 내부 | 원안 LV001에 창고·연결 통로가 있음. 웹에는 실제 입장 가능한 실내가 없음 | 원안 미구현 공간을 수직 탐험과 연결 |
| 계단·층 구분 | 원안에는 `navFloorId` 구분이 있지만 웹에는 없음 | 웹 이동·공격·AI·목표 선택에 실제 높이/층 도입 |
| 입력 | 원안 우클릭 회수, 현재 우클릭 이동. Space는 현재 회피 | 현재 사용자가 익힌 우클릭 이동 유지. 점프와 회피 키 충돌 해소 필요 |
| 시점 | 원안 고정 직교 시점, 웹은 원근 쿼터뷰와 P 촬영 회전 | 쿼터뷰 유지 제안. 실내·등반용 가려짐/추적 보완 |

이는 기존 버그를 고치는 것만이 아니라 **게임의 이동 설계를 확장하는 변경**이다. 원안 전체를 자동으로 폐기하거나, 원안의 모든 수치를 웹에 바로 적용하지 않는다.

## 2. 문서 적용 원칙과 우선순위

- 판정과 시각 표현을 분리한다. 모션·입자가 생략되거나 프레임이 낮아져도 피해·이동·보상 결과는 같아야 한다.
- 상태와 규칙은 테스트 가능한 모듈에서 관리하고, 렌더링은 결과를 표시한다. 새 서버·별도 엔진 프로젝트·범용 프레임워크를 추가하지 않는다. 검증 실행은 기존 `npm test` 경로를 활용한다.
- 구현에 앞서 단계별 재현 사례와 테스트를 작성·검토하고, 실패 확인 → 최소 구현 → 회귀 검사로 진행한다.
- 배경 건물 전체의 내부화, 모든 외벽 자유 등반, 대규모 파괴는 이번 첫 검증 구간과 분리한다.
- 웹 세이브를 보존한다. 기존 임무 완료·의뢰·보상에 영향을 주는 데이터 변경은 이전 형식 변환을 포함한다.
- 아래 모든 신규 수치·키 배치·모션 이름·파일 경로는 **제안**이며 이미 적용된 설정이 아니다.

| 우선순위 | 의미 |
|---|---|
| P0 | 기반/진행 안전. 없으면 새 이동 기능을 신뢰할 수 없음 |
| P1 | 사용자가 요청한 다음 플레이 구간의 핵심 기능 |
| P2 | 해당 기능의 완성도를 높이거나 원안의 게임 루프를 채우는 후속 기능 |
| P3 | 별도 범위·비용 판단이 필요한 선택 확장 |

### 상태를 과대평가하지 않기 위한 확인 사항

- 포함된 `field-operator.glb`의 애니메이션은 **Idle, Walk, Run, TPose**다. TPose는 제작용 기준 자세이며 게임 행동이 아니다. 공격/방어/점프 클립이 숨어 있는 상태가 아니다.
- `world.update()`는 이동 중 `Walk/Run`, 정지 중 `Idle`을 고른다. `attackPose`는 손 근처 광량만 바꾸며 공격 클립을 재생하지 않는다. 회피 때도 `Run`을 사용한다.
- 노면 반사·그림자·잔물결은 시각 표현이다. 이들이 있다고 해서 물리 지면·물·발판 판정이 생기는 것은 아니다.
- 원안 `animation_list.csv`의 56개 항목은 제작 계획이다. 현재 파일의 `Planned` 표기와 실제 게임 반입 여부는 분리해서 추적해야 한다.
- 오늘 `npm --prefix web test`로 47개 테스트 통과를 재확인했다. 이 테스트에는 아직 점프·등반·실내·낙하 피해 검증이 없다.

## 4. 새 기능 전에 해결할 공통 기반 — P0

### 4.1 높이와 충돌

**FR-01 — 3차원 이동 판정:** 플레이어가 발판 위로 이동하면 해당 표면 높이에 접지하고, 발판을 벗어나면 낙하해야 한다. 같은 X/Z의 바닥·천장·옥상을 구분해야 한다.

- 위치 `x/y/z`, 수직 속도, 접지 여부, 지지 표면 ID, 실내/층 ID, 마지막 안전 접지 위치가 필요하다.
- 시각 메시와 단순 충돌 도형을 분리한다. 장식 창문·나뭇잎을 전부 물리 충돌체로 만들지 않는다.
- 기존 사각 장애물에 높이만 붙이는 방식으로 끝내지 않는다. 발판 윗면, 옆면, 천장, 경사로, 출입구 구멍을 각각 판정할 수 있어야 한다.
- 이동하는 캐릭터 몸체의 부피를 검사한다. 발 위치만 확인하면 머리가 천장을 뚫거나 등반 중 몸이 벽에 끼일 수 있다.
- 첫 단계는 고정 지형을 대상으로 한다. 움직이는 발판/엘리베이터는 별도 P2 작업이다.
- 물리 라이브러리 채택 여부는 작은 시험 맵에서 접지·계단·벽 관통을 비교한 후 확정한다. 이번 문서에서는 새 라이브러리/API를 선택하거나 설치하지 않는다.

### 4.2 시간·상태·이벤트

**FR-02 — 공통 행동 상태:** 죽음·강제 피격·이동·공중·등반·상호작용·공격 사이의 허용/중단 규칙을 명시한다. 한 행동의 결과를 중복 적용하지 않는다.

- 이동 상태 예: `Grounded → JumpRise → Fall → Land → Grounded`, `Grounded/Fall → LedgeHang → Mantle → Grounded`, `Grounded → Climb → Grounded/Fall`.
- 전투 상태 예: `Ready → Startup → Active → Recovery → Ready`, 방어는 `Cast → Hold → HitReact/Break/End`.
- 이동 상태와 전투 상태를 무조건 하나의 거대한 상태 목록으로 합치지 않는다. 둘 사이에 ‘등반 중 공격 불가’ 같은 허용표를 둔다.
- 권위 있는 게임 시간표가 판정을 결정하고 모션/이펙트/소리가 이를 따른다. 애니메이션 이벤트 하나가 누락됐다고 공격이나 보상이 사라지면 안 된다.
- 현재는 렌더 주기 안에서 `dt`를 최대 0.05초로 제한한다. 수직 물리를 추가할 때 고정 논리 스텝·누적 시간·최대 보정 횟수·표시 보간을 검토한다. 숨김 탭에서 돌아왔을 때 누적 시간을 한꺼번에 적용해 추락사시키지 않는다.
- 일시정지 시 이동만이 아니라 낙하, 체력 소모, 공격 시간표, 임무 타이머를 함께 멈춘다. 장식 물결처럼 계속 움직여도 되는 표현은 별도 시간으로 구분한다.

### 4.3 입체 경로·공격·상호작용

**FR-03 — 높이를 인식하는 목표 선택:** 우클릭 도착점, 조준 대상, 회수품, NPC, 문은 실제 접근 가능한 표면/공간을 기준으로 골라야 한다.

- 현재 마우스 이동은 Y=0 평면과의 교점을 사용한다. 이를 이동 가능 표면 선택으로 변경하고, 옥상을 클릭했는지 아래 바닥을 클릭했는지 표시한다.
- 바닥 간 연결에는 계단·문·사다리·등반 링크와 통과 조건을 둔다. 층 안 경로와 층 사이 연결 경로를 함께 계산한다.
- 첫 버전의 우클릭은 안전한 걷기·계단·열린 문 경로를 이용한다. 자동 낭떠러지 점프/위험한 낙하는 하지 않고, 수동 이동 링크 앞에서 안내 후 멈추는 방식을 제안한다.
- 같은 X/Z의 위층 적에게 바닥을 뚫고 피해가 들어가거나 아래층 아이템을 E로 먹을 수 없어야 한다. 가까운 거리뿐 아니라 높이·장애물·시야를 확인한다.
- 현재 `takeDamage()`는 대시 중 피해를 회피하고 정면 방벽으로 막는다. 낙하 피해를 이 함수에 그대로 넣으면 대시/방벽으로 추락 피해가 면제될 수 있다. 피해 종류와 무적/방어 적용 대상을 먼저 분리한다.

### 4.4 진행 복구

**FR-04 — 실패해도 계속 플레이 가능:** 지형에 끼이거나 치명적 추락을 해도 유효한 안전 지점으로 복귀할 수 있어야 한다.

- 마지막 안전 접지 위치와 임무 체크포인트는 구분한다. 전자는 끼임 복구용, 후자는 사망·중단 후 임무 재개용이다.
- 로딩·포털 이동·재출동은 낙하 거리 계산에서 제외한다. 등반 중간/문 안/닫힌 공간에는 복구 위치를 저장하지 않는다.
- 적, 드롭, 소비한 물품, 문, 목표, 구조 인원, 보상을 같은 체크포인트 기준으로 복원해 복제/진행 불능을 막는다.
- 기존 세이브의 누락 필드는 안전한 기본값으로 변환하고, 변환 실패 시 원본을 보존한다.
- 경제를 추가할 때 `parseCampaign()`도 바꿔야 한다. 현재 크레딧은 ‘완료 보상 합계와 정확히 같음’을 검사하므로 소비만 추가하면 정상 구매 후 저장도 잘못된 데이터로 판정된다.

## 5. 요청 기능별 상세 기획 — P1

### FR-05. 점프·공중 이동·착지

**목표 경험:** 낮은 장애물과 틈을 직접 넘되, 시작·공중·착지가 명확히 연결된다.

- 준비 → 도약 → 상승 → 정점 → 하강 → 착지 → 제어 복귀로 나눈다. 걷기/달리기 점프는 같은 판정을 공유하고 속도에 맞춰 모션을 혼합한다.
- 접지 상태에서만 기본 점프를 허용한다. 초기 버전에는 이중 점프·무한 공중 대시를 넣지 않는다.
- 공중 방향 조절은 제한적으로 허용한다. 미끄러진 가장자리의 짧은 입력 유예와 착지 직전 점프 입력 예약을 제공하되 무한 재도약을 막는다.
- 낮은 천장에 머리가 닿으면 상승 속도를 제거하고 하강한다. 벽 옆 연타로 높이가 누적되면 안 된다.
- 착지 지형에 맞는 발소리·먼지/물방울과 가벼운 무릎 굽힘을 연결한다. 원형 그림자/목적지 표식도 실제 접지 표면을 따른다.
- **시험용 제안값:** 점프 높이 약 1.1m, 중력 18m/s²이면 초기 수직 속도 약 6.29m/s, 같은 높이까지 비행 시간 약 0.70초. 현재 달리기 속도 4.4m/s를 유지할 경우 이상적인 수평 거리는 약 3.1m다. 실제 도달 거리는 제어·충돌·발판 여유로 줄어들므로 맵은 이 최대치에 맞춰 강제하지 않는다.
- **완료 기준:** 30/60 FPS에서 높이·도달 위치 차이가 허용 오차 안에 있고, 낮은 천장/벽/가장자리/착지 연타에서 관통·무한 점프가 없다.

### FR-06. 단차·장애물 올라타기·넘기

구분 없이 모두 ‘점프’로 처리하지 않는다.

| 상황 | 제안 행동 | 필요한 검사 |
|---|---|---|
| 작은 턱 | 자동 올라서기 | 허용 단차·경사, 머리 위 공간 |
| 낮은 상자·화단 | 점프로 올라가 서기 | 충돌 가능한 윗면, 발판 크기, 착지 가능성 |
| 낮고 얇은 난간 | 넘어가기(Vault) | 반대편 안전 착지 위치, 통제선 여부 |
| 가슴 높이 턱 | 손으로 잡고 올라가기(Mantle) | 잡을 모서리, 몸체 공간, 정상 바닥 |
| 높은 모서리 | 매달리기 → 좌우 이동/올라가기/놓기 | 손잡이 연속성, 정지 공간, 체력/입력 |

첫 검증 높이 후보는 자동 단차 0.25m 이하, 낮은 발판 0.6~0.9m, 손으로 올라갈 턱 1.2~1.6m다. 캐릭터 캡슐과 새 리그 신장에 맞춰 조정한다. 모든 상자·화단을 등반 가능하게 만들지 않고 명시된 표면만 허용한다.

**완료 기준:** 발판 위에서 걷기·공격·방어 가능, 끝을 넘으면 실제 낙하, 도착 공간이 막힌 모서리는 올라타기 시작 전에 거절. 정상에 선 뒤에도 기존 목적지가 남아 자동으로 뛰어내리지 않아야 한다.

### FR-07. 건물 내부 진입

**첫 구현 범위 제안:** 물류센터에 연결된 창고 1동, 출입문 1개, 지상층, 계단, 2층 통로/옥상 중 최소 1개, 반대편 귀환 동선.

- 입장 가능 건물은 문/간판/상호작용 안내로 구분한다. 배경 외관만 있는 건물은 닫힌 상태를 명확히 보여 준다.
- 문은 닫힘·열림·잠김·전환 중 상태를 갖는다. 문을 여는 동안 플레이어/적과 겹치지 않고, 닫힐 때 동선이 바뀌면 경로를 다시 계산한다.
- 단순히 장면을 재로드해 실내처럼 보이게 만들지 않는다. 현재 `enterZone()`는 임무 상태를 새로 만들므로, 같은 미션의 실내 출입에 그대로 쓰면 적·구조 진행이 초기화된다.
- 실내 전환은 동일 미션 상태를 유지한 방 전환 또는 상태를 보존한 하위 장면 로딩으로 구성한다. 문을 나갔다 와도 물품·적·목표가 복제되지 않아야 한다.
- 천장·플레이어 앞 벽은 표시만 가리고 충돌은 유지한다. 방을 벗어나면 표시를 복원한다. 원래 한 재질로 합친 건물 전체를 통째로 가리지 않도록 방/외벽 단위 분리가 필요하다.
- 창문·출입구 빛, 실내 노출, 가구 그림자, 발소리/잔향을 구분하되 너무 어두워 목표가 안 보이지 않게 한다.
- **완료 기준:** 출입문 왕복, 다른 층 이동, 실내 전투/수집 후 재입장, 저장 복원에서 상태 유지. 닫힌 벽·천장을 통한 피격/상호작용 없음.

### FR-08. 외벽 등반

**권장 첫 범위:** 사다리·배관·난간·돌출 손잡이가 있는 **지정 등반 경로**. 모든 외벽을 자유롭게 타는 방식은 별도 확장으로 둔다. 이는 제안이며 사용자의 자유 등반 선호를 제한하는 확정 결정은 아니다.

- 등반 가능한 면, 시작/끝 지점, 벽 법선, 손발 위치, 높이, 허용 좌우 이동 범위를 데이터로 둔다.
- 진입 → 손잡이 잡기 → 상하/좌우 이동 → 휴식 → 정상 올라서기 또는 내려오기 → 지상 복귀를 구현한다.
- 벽 이동 방향을 사용하고 지상 카메라 상대 이동과 구분한다. 카메라 각도가 바뀌어도 위 입력이 벽을 따라 올라가는 동작이어야 한다.
- 첫 버전은 등반 중 공격/방어/회피를 막는 안을 제안한다. 떨어짐은 점프의 하강/착지 흐름을 재사용한다.
- 스태미나를 도입한다면 지상 휴식·안전 발판에서 회복하고, 0이 될 때 즉시 추락하는지 짧게 버티는지 경고와 함께 확정한다. 아직 HUD·소모/회복 코드가 없으므로 무료 등반 검증 단계와 분리한다.
- 정상에 장애물이 있으면 올라타지 않고 매달림을 유지한다. 벽을 놓을 때 몸체를 벽 밖의 유효 공간에 배치한다.
- **완료 기준:** 가능한 벽에서만 진입, 정상·하단 이탈 정상 처리, 모서리 끼임/벽 관통 없음, 실패 후 안전 복구 가능. 필수 구조 구간을 벽타기로 우회해 보상을 받을 수 없음.

### FR-09. 낙하 피해·추락 복구

**목표 경험:** 낮은 점프는 편하게, 높은 곳에서 떨어질 때는 위험을 납득할 수 있게 만든다.

- 접지를 잃은 순간부터 공중 최고점과 실제 착지 높이를 추적한다. 지면에 닿는 프레임에 **한 번만** 피해를 적용한다.
- 첫 정적 지형 버전은 `유효 낙하 높이 = 공중 최고점 − 착지 표면 높이` 방식으로 검증한다. 나중에 움직이는 발판/발사 장치를 추가하면 상대 수직 충돌 속도 기준과 비교한다.
- 시험용 피해안: `floor(최대HP × min(1, 0.08 × max(0, 낙하높이 − 3)²))`. 3m까지 0, 4m에서 최대HP 120 기준 9, 5m에서 38, 6m에서 86, 약 6.54m 이상에서 120이다. **실제 인체 손상 모델이나 확정 밸런스가 아니며 게임용 조정안이다.**
- 작은 점프에는 착지 모션만, 위험한 낙하에는 강한 착지·피격·짧은 제어 제한·피해 UI를 연결한다. 완충 착지는 첫 버전에서 필수가 아니며 이후 감면 기술로 검토한다.
- 낙하 피해는 정면 방벽·일반 대시 무적으로 막지 않는 안을 기본으로 한다. `Fall`, `Enemy`, `Hazard`, `Void` 등 피해 원인을 구분한다.
- 임무 완료의 전투 면제를 지형 안전 면제로 사용하지 않는다. 보상 지급 후 추락해도 결과 재지급 없이 정상 복구되어야 한다.
- 맵 밖/바닥이 없는 공간은 별도 위험 볼륨으로 검출한다. 임시 마지막 안전 지점 복귀와 사망 체크포인트 복귀를 구분하고, 복귀 직후 또 추락하는 반복을 막는다.
- 광장은 전투 안전 구역과 낙하 안전 정책을 구분한다. 첫 학습 구간은 높은 추락을 막거나 무피해 복귀시키는 방식을 제안한다.
- **완료 기준:** 임계값 전후·동일 높이 점프·계단 하행·천장 충돌·등반 이탈·일시정지 복귀·사망에서 예상 피해와 복구가 일치하고 중복 피해가 없다.

### 6.1 플레이어 모션 세트

|---|---|---|---|

| 이동 전환 | StartMove, Stop, TurnLeft/Right, Backpedal, Strafe | 없음 | P1. 급회전·정지·조준 이동 전환 |

| 매달림 | LedgeCatch, HangIdle, ShimmyLeft/Right, PullUp, Drop | 없음 | P1. 수직 이동 검증 후 |

| 방어 | ShieldCast, ShieldHold, ShieldHit, ShieldBreak, ShieldEnd | 방벽 표시만 있음 | P1. 정면·파손·만료를 다른 반응으로 표현 |

| 회수 | ReclaimStart/Loop/End, Pickup | 즉시 회수/궤적 | P1 기본, P2 채널·이동 혼합 |
| 상호작용 | DoorOpen, Switch, Inspect, Heal, RescueBrace | 상태 변경만 있음 | P1 문, P2 작업·치료·구조 |
| 대화/일상 | Talk, Nod, LookAt, WorkIdle | 플레이어 전용 없음 | P2. 말하는 사람·대상에 맞춘 시선 |

### 6.2 공격·방어를 ‘동작’으로 만드는 기준 — FR-10

**기본 공격 한 번의 시험 시간표:** 준비 0.12초 → 판정 이벤트 0.12초 → 회수/후딜 → 총 0.45초 종료. 현재 0.45초 간격을 유지하면서 시험하는 안이다. 원안 Attack01 타격 0.18초와 다르므로 애니메이터의 결과와 플레이 테스트 후 하나로 통일한다.

- 손/도구가 공격 방향을 향하고 정해진 소켓에서 효과가 시작한다. 현재 모델에서 왼손 본을 찾는 코드가 있지만 효과 시작점에 실제 연결하지는 않는다.
- 공격 인스턴스 ID와 대상 ID로 중복 판정을 방지한다. 저FPS에서 판정 시각을 건너뛰어도 한 번 발생하고, 반복 재생/블렌딩으로 두 번 발생하지 않게 한다.
- 이동 속도와 조준 방향을 분리한다. 움직이면서 공격할 경우 하체는 보행, 상체는 조준/시전하도록 설계한다. 전신 공격은 제어 제한을 명시한다.
- Q는 현재 ‘누르면 3초 방벽’이다. 우선 이 규칙을 유지하면서 시전/유지/피격 모션을 붙이고, 누르고 있는 동안 방어하는 방식은 별도 선택으로 둔다.
- 방벽 생성 타이밍과 준비 모션을 맞춘다. 생성 전 선딜에 방어가 가능한지, 움직임 속도 제한이 있는지 명확히 표시한다.
- 깨짐과 자연 만료를 다르게 표현한다. 방벽 뒤에서 맞으면 방어 성공 소리를 내지 않는다.
- 퍼펙트 가드/패링, 콤보, 차지 공격, 공중 공격은 기본 공격·방어가 안정화된 뒤 P2로 검토한다. 이번 요청을 이유로 모두 첫 단계 필수로 넣지 않는다.

**취소/동시 입력 초안:**

| 상태 | 이동 | 기본 공격 | Q 방어 | 점프/회피 | E 상호작용 |
|---|---|---|---|---|---|
| 지상 대기/보행 | 허용 | 허용 | 허용 | 허용 | 대상이 유효할 때 |
| 공격 준비/판정 | 행동별 감속 | 재시작 금지 | 첫 버전 금지 | 지정 취소 구간만 | 금지 |
| 공격 후딜 | 제한 해제 구간 명시 | 짧은 예약만 | 회복 후 | 지정 취소 구간만 | 회복 후 |
| 공중 | 제한 조절 | 첫 버전 금지 | 첫 버전 금지 | 이중 점프·공중 대시 금지 | 등반 잡기만 예외 |
| 매달림/등반 | 벽 방향으로 | 금지 | 금지 | 놓기/정상 이탈만 | 등반 전용 동작만 |
| 강한 착지/피격 | 잠시 제한 | 금지 | 금지 | 회복 후 | 금지 |
| 사망/로딩/모달 | 금지 | 금지 | 금지 | 금지 | 창 조작만 |

정면 방벽의 방향 고정/추적, 기존 활성 방벽의 점프 시 해제 여부, 자원 환급은 구현 전 세부 표로 확정한다. 첫 버전은 점프·등반 진입 시 기존 방벽을 종료하고 이미 지불한 에너지는 환급하지 않는 안을 제안한다.

### 6.3 적·보스·NPC·구조 인물 — FR-11

- 일반 적: 대기, 탐색/추적 보행, 회전, 공격 준비, 돌진/발사, 회복, 피격, 경직, 사망을 각각 표현한다. 경고 모양·실제 공격 범위가 같은 방향/높이를 사용해야 한다.
- 보스: 일반 적 확대 모델에서 분리한다. 원안의 포크 공격, 기둥 충돌, 연결부 노출, 단계 전환, 무너짐에 대응하는 전용 실루엣과 모션이 필요하다.
- 백기석: 인원 확인·팔짱·작업 지시, 한서린: 진료·무릎 꿇기·의료품 확인, 오미라: 기록·명패 확인, 강도윤: 무전·수신호·순찰을 우선 후보로 둔다.
- 광장 이미지 NPC는 표정·몸 회전·손 작업·실내 이동을 제대로 표현하기 어렵다. 대화 원화는 UI에 유지하고, 월드 인물은 리그가 있는 3D 모델로 단계적으로 교체하는 안을 제안한다.
- 구조 인물은 대기·불안·걷기/달리기·부축·도착 후 안도 모션을 갖춰야 한다. 모션 재생과 실제 구조 인원 집계는 분리한다.
- 서로 다른 층에 있는 적이 플레이어를 바로 밀거나 때릴 수 없어야 한다. 적이 올라갈 수 없는 발판은 원거리 대응/귀환 등 규칙이 필요하며 갑자기 순간이동시키지 않는다.

### 6.4 아트 반입 완료 기준

- 실제 모델의 전방/축/스케일과 충돌 캡슐을 맞춘다. 현재 임시 인물 높이 1.82m와 원안 TK01 1.78m를 혼용하지 않는다.
- 모든 추가 모션은 동일 리그에 리타깃하고, 왼팔 장갑·어깨·손·무릎 관통과 발 미끄러짐을 검사한다.
- 일반 이동은 코드 이동 + 제자리 모션을 우선한다. 등반/넘기처럼 시작·끝 지점이 중요한 동작은 궤적을 맞추되 코드 이동과 루트 이동을 동시에 더하지 않는다.
- 손/발 위치 보정(IK)은 계단·벽 접촉 품질을 높이는 P2다. 기본 리그·정상 판정 없이 IK만으로 해결하지 않는다.
- 모션 목록에는 ID, 파일, 리그, 반복 여부, 시작/판정/종료 시각, 이동 제어, 취소 규칙, 품질 검수, 출처를 기록한다.
- 원화 생성과 리깅 애니메이션 제작은 별개 작업이다. 향후 외부 모션/모델을 반입할 때 출처·사용 범위·파일 크기를 기록한다.

## 7. 이펙트와 사운드 계획 — FR-12

- 품질 단계에 따라 입자 수·빛·데칼을 줄이되 위험 범위와 타격 확인은 남긴다. 장식 파편을 줄여도 공격력/회수량은 변하지 않는다.

- 방벽 유지음·등반 마찰음은 행동 종료, 창 열기, 사망, 구역 전환에서 남지 않아야 한다.

## 8. 맵 확장안 — FR-13

### 첫 검증 구간의 연결 구조

```text
귀환광장
  └─ 물류센터 진입 안전 구역 / 체크포인트
       ├─ 낮은 발판 학습 → 상자 위 전투 → 안전한 하강
       └─ 창고 문 → 창고 1층 → 계단 → 상부 통로/옥상
                                      ├─ 지정 외벽/사다리 → 외부 귀환 동선
                                      └─ 선택 기록/보급품 → 안전한 하강 경로
```

맵을 먼저 크게 만드는 것보다 서로 다른 이동과 판정을 한 공간에서 시험하는 것이 목적이다. 기존 M001 필수 조사·지지점·7명 구조·보스·귀환 조건은 유지하며, 새 동선이 이 조건을 의도치 않게 생략하지 않게 한다.

| 공간 | 초기 확장 제안 | 완료 기준 |
|---|---|---|
| 광장 | 낮은 연습 발판, 간단한 이동 안내, 허수아비 후보 | 전투 안전과 학습 안전 보장. NPC 대화 동선 유지 |
| 물류센터 | 골목·적재장·창고·상부 통로를 연결한 검증 구간 | 전체 동선 왕복, 필수 구조 경로, 적·문·낙하 검증 |
| 학교 | 교실/보건실·복도·계단, 옥상 대피 동선 후보 | 학생 구조 경로가 문/층에 막히지 않음 |
| 기록 보관구역 | 서고·관리실, 컨테이너 상부 동선, 잠금 해제 | 기록 수집·우회 경로·보스 출현 순서 유지 |
| 외곽 도시 | 기존 원경 유지, 일부 건물만 플레이 공간으로 승격 | 보이지 않는 바닥/벽, 끝없는 추락, 배경 진입 없음 |

현재 이동 구역 크기는 광장 32×34m, 물류센터 9.8×40m, 학교 26×40m, 보관구역 30×40m다. 원안 LV001 96×64m는 참고 목표이지 현재 완성된 크기가 아니다. 확장 범위는 검증 구간의 밀도·성능·플레이 시간을 확인한 뒤 결정한다.

### 맵 제작 시 필수 메타데이터

- 공간 ID, 방/층 ID, 이동 바닥/경사, 충돌 도형, 출입 링크, 잠금 조건.
- 발판/넘기/등반 가능 여부와 시작·종료 위치, 안전 착지 표면.
- 위험 볼륨, 낙하 정책, 복구 지점, 스폰 허용 영역.
- 카메라 가림 그룹, 조명/반사 구역, 오디오 표면/실내 구역.
- 임무 목표·의뢰·NPC·구조 경로의 높이와 공간 참조.

검증 도구는 끊긴 출입 링크, 접근 불가능한 목표, 닫힌 방의 스폰, 등반 끝점에 바닥이 없는 경우를 경고해야 한다. 점프력이 커져도 기존 이동 한계를 무시하고 도시 배경까지 갈 수 있게 하지 않는다.

## 10. 조작 변경안과 미확정 선택

현재 동작은 그대로 두고, 실제 이동 기능 구현 시 아래 안을 적용하는 방식을 제안한다.

| 행동 | 현재 | 확장안 |
|---|---|---|
| 걷기/달리기 | WASD / Shift | 유지 |
| 지정 이동 | 우클릭 | 유지. 높이·층·위험 경로 판정 추가 |
| 기본 공격 / 방벽 | 좌클릭 / Q | 유지. 판정과 모션 연결 |
| 점프 | 없음 | Space 후보 |
| 회피 | Space | C 후보. 원안의 C 권역과 충돌하므로 권역 키 재배치 필요 |
| 대화·물품·문 | E | 유지. 대상과 행동 문구 명시 |
| 등반 진입/이탈 | 없음 | 근처 등반 링크에서 E 후보. 대화/문/물품과 겹치면 명시적 대상 선택 |
| 벽 이동/올라서기 | 없음 | WASD, 정상에서 Space 후보 |
| 임무·촬영·설정 | J / P / Esc | 현재 토글 규칙 유지 |

구현 전 확정할 항목:

1. **등반 범위:** 지정 경로 우선(제안) 또는 대부분의 외벽 자유 등반.
2. **방어 방식:** 현재 3초 유지형 우선(제안) 또는 누르고 있는 동안 방어.
3. **공중 전투:** 첫 단계에서는 금지(제안), 이후 공중 공격/방어 추가 여부.
4. **스태미나:** 무료 등반으로 접촉/이탈부터 검증(제안), 이후 자원 제한 여부.
5. **낙하 난이도:** 광장 학습은 무피해/차단, 현장은 피해(제안). 이야기 난이도 감면 여부.
6. **실내 연결:** 같은 미션 상태를 유지하는 작은 실내 1개부터(제안), 다층 건물 전체 범위.
7. **키 배치:** Space 점프/C 회피 후보의 사용감, 향후 도식 슬롯과 중복 제거.

위 항목은 문서 작성의 장애물이 아니라 **구현 착수 전 선택할 결정 목록**이다. 사용자 요청인 점프·실내·외벽·낙하 피해 자체를 미정으로 되돌리는 것은 아니다.

### 성능·신뢰성 합격 기준 제안

- 기준 PC·브라우저·창 해상도·품질·장면·적 수를 고정한 후 목표를 확정한다. 기본 목표는 균형 모드 60 FPS, 성능 우선 30 FPS이며 현재 달성 보장이 아니다.
- 60 FPS의 전체 프레임 예산은 약 16.7ms다. 물리·애니메이션·효과·렌더 비용을 분리해서 기록하고 효과 때문에 충돌 검사나 적 경고를 생략하지 않는다.
- 같은 검증 동선에서 기존 대비 프레임 시간과 메모리 추이를 기록한다. 20회 실내 왕복·10분 전투 뒤 자원이 계속 증가하는지 확인하고 수치와 화면을 남긴다.
- 두 프레임 설정의 동일 점프 시험에서 도달 높이/위치 차이 5cm 이내를 초기 목표로 제안한다. 충돌 경계의 수치 허용 오차는 별도 고정한다.
- 첫 구간의 통과 조건은 벽/천장 관통, 정상 끼임, 영구 진행 불능, 보상 복제 0건이다. 알려진 실패가 있으면 확대 단계로 넘어가지 않는다.
- 브라우저 저장 공간 부족·페이지 중단·그래픽 연결 끊김에서 안내하고 기존 진행 데이터를 보존한다. 이번 단계에서는 온라인 계정/서버 저장을 필수로 추가하지 않는다.

## 15. 구현 착수 검토와 첫 작업 범위

2026-09-08 사용자 요청: 문서를 검토해 적절하면 커밋·푸시한 뒤 구현 시작. 검토 결과 **전체 방향은 타당하며 아래 단계 분리 조건으로 착수 가능**하다. 이 판단은 전체 계획 구현 완료나 모든 세부안 최종 확정을 뜻하지 않는다.

보완한 사항:

1. **기반과 완성형 저장을 한 번에 만들 필요는 없다.** 보상/미션 진행이 없는 독립 이동 훈련 구역에서 먼저 충돌·점프·낙하·재시도를 검증한다. 기존 임무에 실내/등반을 연결하기 전에는 T04의 체크포인트 보존을 완료해야 한다. 시험 구역의 위치 복구를 완성형 미션 체크포인트로 표시하지 않는다.
2. **새 높이 판정이 없는 기존 소품은 임의로 발판화하지 않는다.** 훈련용 발판은 같은 치수 데이터로 표시와 충돌을 만든다. 기존 맵의 장애물/경계는 계속 차단하고, 높이를 정식 반입한 물체부터 올라설 수 있게 한다.
3. **일시적인 낮은 FPS에서도 충돌 판정을 건너뛰지 않는다.** 논리 스텝을 작은 일정 간격으로 진행하고, 탭 숨김·모달·로딩 동안 누적된 시간은 복귀 시 추락에 적용하지 않는다. 장시간 정지의 무한 따라잡기를 금지한다.
4. **발판 위 전투의 임시 규칙이 필요하다.** 공중에서 공격/방어/회피/일반 상호작용을 막고, 다른 높이의 대상은 기존 평면 공격/회수에서 제외한다. 완성형 입체 전투·층 간 조준은 T03/T10에서 확장한다.

### S01 — 이번 첫 구현 단위

- 평지와 직육면체 발판/천장에 대한 높이·수직 충돌, 접지/낙하 상태.
- Space 점프, C 회피로 변경하고 화면 도움말도 함께 갱신. 기존 J/P/Esc 토글 유지.
- 다단 훈련 발판, 낮은 천장, 안전한 시작점과 높은 발판에서 내려오는 낙하 피해 체험.
- 낮은 점프는 무피해, 높은 낙하는 1회 피해. 대시/방벽으로 낙하 피해를 지우지 않음.
- 마지막 안전 위치 복구와 사망 후 훈련 재시작. 훈련은 캠페인/재화를 변경하지 않음.
- 높이에 맞는 인물·바닥 표식·착지 효과·카메라 추적. 점프 포즈는 기존 리그의 절차형 초기 표현으로 시작하며 전용 아트 클립 반입 완료로 표시하지 않음.
- 같은 높이 발판 안의 우클릭 이동은 허용하되, 자동 점프/다른 높이 이동은 안내 후 거절. 완성형 층 연결 경로는 후속 작업.

검증은 `web/tests/vertical-movement.test.js` 등 새 실패 테스트로 시작한다. 점프 궤적 30/60 FPS, 상자 착지/옆면, 천장 충돌, 벽 관통, 낙하 피해 1회, 공중 행동 차단, 평면 목표 높이 오판 방지, 복구/재시작과 기존 47개 회귀 테스트를 확인한다. 문서 승인 요청을 다시 반복하지 않고, 사용자가 위임한 검토 판단에 따라 이 범위의 구현을 진행한다.

S01에 포함하지 않는 것: 문/실내 입장, 외벽 등반, 완성형 미션 체크포인트, 계단·경사·움직이는 발판, 전용 공격/방어 클립, 전체 모션 교체. 이들은 삭제한 요구가 아니라 S01 검증 후 이어갈 다음 단계다.
