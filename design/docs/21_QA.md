# 테스트 계획과 결함 보고

## 테스트 계층
규칙 테스트는 피해, 회수, 드롭 합, 성장, 거래와 저장을 다룬다. 통합 테스트는 전투 상태, 임무 스크립트와 보상을 연결한다. 실제 플레이 검사는 카메라, 가독성, 조작감, 구조 흐름을 확인한다. 수치 검증이 통과해도 플레이 재미와 성능이 검증됐다고 보지 않는다. QA_cases.csv에 전제, 절차, 기대 결과, 중요도와 실행 상태를 기록한다.

## 주요 테스트
공격력 20과 방어력 20의 기본 피해가 16인지 확인한다. 에너지 95에서 토큰 8을 회수했을 때 100과 잔량 3인지 확인한다. 같은 토큰을 두 번 요청해도 중복 지급되지 않아야 한다. 구조 필수 인원 미달에서 보스를 쓰러뜨려도 임무 성공이 되면 안 된다. 거래 직후 강제 종료와 저장 중 종료에서 재화 손실 및 중복을 확인한다. 게임패드 해제와 재연결 후 포커스가 살아 있어야 한다.

## 결함 등급
P0는 실행 불가, 진행 데이터 손상, 무단 데이터 송신이다. P1은 주 임무 진행 불가, 핵심 입력 불가, 반복 크래시다. P2는 비핵심 콘텐츠 오류와 뚜렷한 가독성 결함, P3는 작은 시각 불일치다. 발견 빈도와 영향 범위를 별도로 기록하고 재현 빈도가 낮다는 이유로 데이터 손상을 낮게 분류하지 않는다.

## 보고 양식
bug_template.md는 제목, 빌드 ID, 플랫폼 및 사양, 발생 씬, 전제, 재현 단계, 기대 결과, 실제 결과, 빈도, 로그, 첨부, 심각도, 담당, 수정 빌드, 재검증 결과를 제공한다. 사용자 데이터가 들어 있는 로그는 익명화한 뒤 공유한다. 미재현 상태와 해결 상태를 구분한다.

## 출시 차단 기준
미해결 P0와 P1은 0이어야 한다. 새 게임부터 엔딩까지 클린 설치 진행 2회, 기존 세이브 마이그레이션, 오프라인 실행, 입력 재매핑, 한국어 및 영어 UI, 해상도별 레이아웃을 통과해야 한다. 스토어 문구의 기능과 실제 빌드를 대조한다. Windows 테스트를 macOS에서 문서를 작성한 것으로 대체할 수 없다.

## 현재 실행 상태
게임은 아직 제작되지 않았으므로 게임 QA 항목은 전부 Not Run이다. 이 패키지에서 실시하는 검증은 문서 링크, 데이터 수식, 파일 생성과 산출물 표시 검토에 한정한다. 실제 게임 테스트를 통과했다는 보고는 작성하지 않는다.
